# 勤務表自動作成ツール

Python・OR-Tools・openpyxlを使用して、Excel形式の勤務表から勤務希望や必要休日日数を読み取り、条件を考慮しながら休日を自動配置するツールです。

既存のExcel運用を大きく変更せず、

- 希望休や予定を保持する
- 各職員の必要休日日数を満たす
- 病棟ごとの必要人数を考慮する
- 専従・専任・作業療法士の配置を考慮する
- 元のExcelファイルや数式を壊さない

ことを目的として作成しました。

---

## 1. 開発背景

勤務表をExcelで作成する場合、勤務希望を確認しながら、

- 各職員の休日数
- 病棟ごとの人数
- 職種・役割ごとの配置
- 連続勤務
- 有給休暇
- 半日休暇

などを手作業で調整する必要があります。

条件が増えるほど確認作業が複雑になり、修正のたびに別の条件へ影響する問題がありました。

そこで、既存のExcelをそのまま入力として利用し、制約充足問題を扱える **Google OR-Tools CP-SAT Solver** を使って勤務表の作成を自動化しました。

## 4. Excelの基本構造

勤務表では職員を `A〜P` の16名として匿名化しています。

### 病棟構成

| 病棟 | 職員 |
|---|---|
| 1病棟 | A / B / C / D |
| 2病棟 | E / F / G / H / I / J / K |
| 3病棟 | L / M / N / O / P |

役割はA列の氏名から自動判定します。

例：

~~~text
A（専従）
B（専任）
D（作業療法士）
~~~

そのため、Python側で職員のExcel行番号を固定するのではなく、A列を検索して現在の行番号を取得しています。

Excelへ行を追加した場合でも、職員名が正しく入力されていれば対応しやすい設計です。

## 5. 勤務の表記

| Excel上の値 | 意味 |
|---|---|
| 空白 | 通常出勤 |
| `出` | 明示的に入力された出勤予定 |
| `休` | 1日休み |
| `半/` | 半日休み |
| `/半` | 半日休み |

Pythonが新しく通常出勤を割り当てた場合は、Excelには `出` を入力せず**空白のまま**にします。

休日として割り当てた日のみ `休` を入力します。

これにより、生成後も元の勤務表と同じ見た目を維持できます。

## 6. 勤務希望と理由欄

各職員の勤務欄の下に理由欄があります。

理由には以下を使用します。

~~~text
希望
委員会
年休
年/
 /年
研修
特休
出張
~~~

### 最も重要なルール

**勤務と理由の両方が入力されている予定は絶対に変更しません。**

例：

~~~text
勤務：休
理由：希望
~~~

の場合、

~~~text
休
~~~

は固定勤務として扱います。

同様に、

~~~text
勤務：出
理由：委員会
~~~

も固定されます。

OR-Tools側で値を固定するだけでなく、Excelへ結果を書き戻す際にも対象セルを更新しないようにしています。

---

## 7. 自動作成時の優先順位

すべての条件を同じ重要度として扱うと、希望休を変更して人数条件を満たすなど、実運用では望ましくない勤務表になる可能性があります。

そのため、本ツールでは条件に明確な優先順位を設定しています。

~~~text
勤務＋理由が入力された固定予定
            ↓
既にExcelへ入力されている勤務
            ↓
各職員の必要休日日数
            ↓
病棟人数・職種配置・連勤など
~~~

固定予定を守った結果、病棟人数などの条件を満たせない場合でも、固定予定を変更することはありません。

その場合は、可能な範囲で最適な勤務表を作成します。

## 8. 各職員の休日日数

Excel右側の以下の情報を利用します。

| 項目 | 内容 |
|---|---|
| 公休数 | その月に必要な公休日数 |
| 有給数 | 年休・半日年休の合計 |
| 休日数 | 現在割り当てられている休日 |
| 残り | 追加で必要な休日 |

基本的な考え方は、

~~~text
必要休日数 = 公休数 + 有給数
~~~

です。

### 有給の計算

~~~text
年休 = 1日

年/ = 0.5日

/年 = 0.5日
~~~

### 休日の計算

~~~text
休 = 1日

半/ = 0.5日

/半 = 0.5日
~~~

0.5日を正確に扱うため、プログラム内部では休日を「0.5日単位の整数」として管理しています。

例：

~~~text
1日   = 2
0.5日 = 1
10日  = 20
~~~

浮動小数点による誤差を避けながら、OR-Toolsで整数として計算できるようにしています。

## 9. 勤務条件

勤務希望を最優先したうえで、以下の条件をできるだけ満たすよう最適化します。

### 連続勤務

終日の `出` が4日連続する勤務をできるだけ避けます。

~~~text
出 → 出 → 出 → 出
~~~

は避ける対象です。

一方、

~~~text
出 → 半/ → 出 → 出
~~~

~~~text
出 → /半 → 出 → 出
~~~

のように半休を含む場合は、連続した終日勤務として扱いません。

固定予定によって4連続勤務を避けられない場合は、固定予定を優先します。

### 月曜日〜土曜日

各病棟に、

~~~text
専従 または 専任
~~~

が最低1人勤務する状態を優先します。

ただし、専従・専任の固定休が重なった場合は固定予定を優先します。

### 作業療法士

月曜日〜土曜日は、

~~~text
最低1人
可能であれば2人
~~~

の作業療法士が勤務するよう調整します。

### 日曜日

各病棟、

~~~text
2人勤務
~~~

を基準として調整します。

固定予定との矛盾がある場合は、固定予定を優先します。

### 水曜日・木曜日・金曜日

各病棟について、

~~~text
原則：休み2人以内
許容：休み3人
~~~

となるよう調整します。

3人を超える休みには、より大きなペナルティを設定しています。

### 月曜日・火曜日・土曜日

病棟ごとの目安は以下です。

| 病棟 | 目標 |
|---|---|
| 1病棟 | 2〜3人勤務 |
| 2病棟 | 4人勤務 |
| 3病棟 | 3人以上勤務 |

これらも固定勤務を変更してまで満たす条件ではなく、最適化時の目標として扱います。

## 10. 最適化方法

勤務表には、

- 絶対に変更できない条件
- できるだけ守りたい条件

の2種類があります。

本ツールではOR-ToolsのCP-SAT Solverを利用し、さらに優先順位ごとに複数回最適化しています。

### STEP 1：既存予定を維持

理由がない既存の `出` や `休` についても、できるだけ変更しない勤務表を探します。

### STEP 2：休日数の最大差を最小化

1人だけ休日数が大きく不足することを防ぎます。

~~~text
A：休日ぴったり
B：休日ぴったり
C：3日不足
~~~

よりも、

~~~text
A：0.5日不足
B：1日不足
C：1日不足
~~~

のような、偏りの少ない結果を優先します。

### STEP 3：全員の休日数の差を最小化

最大差を抑えた状態で、全職員の休日数のズレをできるだけ0へ近づけます。

### STEP 4：その他の勤務条件を最適化

最後に、

- 病棟人数
- 専従・専任
- 作業療法士
- 4連続勤務
- 1日だけの単発勤務

などを調整します。

この方法により、単純にすべての条件へ大きな重みを付けるのではなく、業務上重要な条件の順番を明確にしています。

## 12. 安全性への対応

Excel業務で使用することを想定し、元データを壊さないことを重視しています。

### 元ファイルは上書きしない

入力：

~~~text
input/kinmu_sample.xlsx
~~~

出力：

~~~text
output/kinmu_output.xlsx
~~~

として完全に分離しています。

### 一時ファイルへ保存してから確定

いきなり完成ファイルへ保存せず、

~~~text
.kinmu_output.tmp.xlsx
~~~

へ保存します。

その後、

- 数式が変更されていないか
- 固定勤務が変更されていないか

を再確認し、問題がなければ `kinmu_output.xlsx` へ置き換えます。

### Excel数式の保護

処理開始時にExcel内の数式を記録し、保存前・保存後に同じ数式が残っているか確認します。

### Excelの再計算

openpyxlはExcel数式自体を計算しないため、出力ファイルをExcelで開いた際に数式が再計算されるよう設定しています。

## 13. 入力チェック

誤ったデータから勤務表を作成しないよう、実行前に入力内容を検証します。

例えば、

~~~text
理由：希望
勤務：空白
~~~

のように理由だけが入力されている場合は、自動的に意味を推測せずエラーとして処理します。

また、

~~~text
年休 → 休

年/ または /年
→ 半/ または /半
~~~

の組み合わせも確認します。

不正な入力がある場合は勤務表を作成せず、問題のセルをターミナルへ表示します。

## 17. 設計上のポイント

このプロジェクトでは、単に「Excelへ休みを書き込む」ことではなく、実際の業務で安全に利用できることを重視しました。

特に意識した点は以下です。

1. **既存業務を大きく変更しない**
   - Excelをそのまま入力・出力として利用

2. **人が入力した予定を最優先する**
   - 勤務＋理由はハード制約として固定

3. **最適化の優先順位を明確にする**
   - 既存予定 → 休日数 → 人員配置の順に調整

4. **数式や元データを壊さない**
   - 保存前後に自動検証

5. **Excelの行番号へ依存しすぎない**
   - 職員をA列から自動検出

6. **半日単位を整数で管理する**
   - 浮動小数点による誤差を回避

7. **不可能な条件を無理に満たさない**
   - 固定予定を変更せず、満たせなかった条件を明示

## 18. 現在の仕様上の制限

現在は以下の仕様です。

- 自動生成する勤務は `通常出勤` または `休` のみ
- `半/`・`/半` は自動生成せず、既存入力のみ保持
- 半休はその日に勤務者として存在するものとして人数計算
- 月をまたいだ連続勤務は現在計算対象外
- Excelのレイアウト・見出しには一定の形式が必要
- GUIはなく、ターミナルから実行
