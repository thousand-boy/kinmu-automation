# 勤務表自動作成ツール

Python・Google OR-Tools・openpyxlを使用して、Excel形式の勤務表から勤務希望や必要休日日数を読み取り、複数の勤務条件を考慮しながら休日を自動配置するツールです。

既存のExcel運用を大きく変更せず、

- 希望休や既存予定を保持する
- 各職員の必要休日日数をできるだけ満たす
- 病棟ごとの必要人数を考慮する
- 専従・専任・作業療法士の配置を考慮する
- 連続勤務をできるだけ避ける
- 元のExcelファイルや数式を壊さない

ことを目的として開発しました。

---

## 1. 開発背景

Excelで勤務表を作成する場合、勤務希望を確認しながら、

- 各職員の休日数
- 病棟ごとの勤務人数
- 職種・役割ごとの配置
- 連続勤務
- 有給休暇
- 半日休暇
- 委員会・研修・出張などの既定予定

を手作業で調整する必要があります。

条件が増えるほど確認作業が複雑になり、1か所を修正すると別の勤務条件へ影響する問題があります。

そこで、既存のExcel勤務表をそのまま入力として利用し、制約充足・最適化問題を扱える **Google OR-Tools CP-SAT Solver** を使って勤務表作成を自動化しました。

単純にランダムで休日を配置するのではなく、

> 「絶対に変更してはいけない条件」と「できるだけ満たしたい条件」

を分け、業務上の優先順位を考慮しながら勤務表を作成します。

## 4. Excelの基本構造

公開用勤務表では、個人情報保護のため職員名を `A〜P` の16名として匿名化しています。

### 現在の病棟構成

| 病棟 | 職員 |
|---|---|
| 1病棟 | A / B / C / D |
| 2病棟 | E / F / G / H / I / J / K |
| 3病棟 | L / M / N / O / P |

### 役割の表記

役割はExcelのA列に記載された名称から自動判定します。

例：

```text
A（専従）
B（専任）
D（作業療法士）
```

Python側ではExcelの行番号を直接固定せず、A列から職員名を検索して現在の行番号を取得しています。

そのため、A〜Pの既存職員については、Excel上の行位置が変更されても対応できます。

一方、現在は職員名と病棟構成をPythonコード側に定義しているため、

- 職員の追加
- 職員の削除
- 名前の変更
- 病棟異動

にはコードの修正が必要です。

今後は、Excelや設定ファイルから職員情報を読み込む「職員マスタ方式」への改善を予定しています。

## 5. 勤務の表記

| Excel上の値 | 意味 |
|---|---|
| 空白 | 通常出勤 |
| `出` | 明示的に入力された出勤予定 |
| `休` | 1日休み |
| `半/` | 半日休み |
| `/半` | 半日休み |

Pythonが新しく通常出勤を割り当てた場合は、Excelへ `出` を入力せず **空白のまま** にします。

休日として割り当てた日のみ `休` を入力します。

これにより、自動作成後も元の勤務表に近い見た目を維持できます。

プログラム内部では、Excel上の空白も「通常出勤」として管理しています。

## 6. 勤務希望と理由欄

各職員の勤務欄の下には理由欄があります。

現在使用している理由は以下です。

```text
希望
委員会
年休
年/
/年
研修
特休
出張
```

### 最も重要なルール

**勤務と理由の両方が入力されている予定は変更しません。**

例えば、

```text
勤務：休
理由：希望
```

の場合、

```text
休
```

は固定勤務として扱います。

同様に、

```text
勤務：出
理由：委員会
```

も固定されます。

固定勤務は、

1. OR-Tools側で変更できない制約として設定
2. Excelへ書き戻す処理でも対象セルを更新しない
3. 保存後に元の値と一致しているか再確認

という複数段階で保護しています。

## 7. ハード制約とソフト制約

本ツールでは勤務条件を大きく2種類に分けています。

### ハード制約

絶対に変更しない条件です。

現在の主なハード制約は、

```text
勤務 + 理由が入力された固定予定
```

です。

### ソフト制約

できるだけ満たしたい条件です。

例えば、

- 必要休日日数
- 病棟勤務人数
- 専従・専任の配置
- 作業療法士の人数
- 4連続勤務の回避
- 日曜日の人数
- 単発勤務の回避

などがあります。

固定予定とソフト制約が矛盾した場合は、固定予定を優先します。

---

## 8. 自動作成時の優先順位

すべての条件を同じ重要度として扱うと、病棟人数を満たすために希望休が変更されるなど、実運用では望ましくない結果になる可能性があります。

そのため、以下の順番で優先します。

```text
勤務＋理由が入力された固定予定
            ↓
既にExcelへ入力されている勤務
            ↓
各職員の必要休日日数
            ↓
病棟人数・職種配置・連勤など
```

固定予定によって病棟人数などの条件を満たせない場合でも、固定予定を変更することはありません。

その条件下で、可能な範囲の勤務表を探索します。

## 9. 各職員の休日日数

Excel右側の以下の項目を利用します。

| 項目 | 内容 |
|---|---|
| 公休数 | その月に必要な公休日数 |
| 有給数 | 年休・半日年休の合計 |
| 休日数 | 現在割り当てられている休日 |
| 残り | 追加で必要な休日 |

基本的な考え方は、

```text
必要休日数 = 公休数 + 有給数
```

です。

### 有給の計算

```text
年休 = 1日
年/  = 0.5日
/年  = 0.5日
```

### 休日の計算

```text
休   = 1日
半/  = 0.5日
/半  = 0.5日
```

### 0.5日を整数として扱う理由

OR-Toolsでは整数を使用して制約を表現するため、内部では休日を「0.5日単位の整数」として管理しています。

```text
0.5日 = 1
1日   = 2
10日  = 20
```

これにより、小数を直接扱うことによる計算誤差を避けています。

## 10. 勤務条件

勤務希望を最優先したうえで、以下の条件をできるだけ満たすように最適化します。

### 4連続勤務を避ける

終日の通常勤務が4日連続する状態をできるだけ避けます。

```text
出 → 出 → 出 → 出
```

は避ける対象です。

一方、

```text
出 → 半/ → 出 → 出
```

や、

```text
出 → /半 → 出 → 出
```

のように半休を含む場合は、連続した終日勤務として扱いません。

固定予定によって4連続勤務を避けられない場合は、固定予定を優先します。

### 月曜日〜土曜日：専従・専任

各病棟に、

```text
専従 または 専任
```

が最低1人勤務する状態を優先します。

ただし、固定休などによって不可能な場合は固定予定を優先します。

### 月曜日〜土曜日：作業療法士

作業療法士は、

```text
最低1人
可能であれば2人
```

勤務する状態を目標とします。

### 日曜日

各病棟、

```text
2人勤務
```

を基準として調整します。

### 水曜日・木曜日・金曜日

病棟ごとの休み人数は、

```text
理想：2人以内
許容：3人
```

となるように調整します。

3人を超える場合は、より大きなペナルティを設定します。

### 月曜日・火曜日・土曜日

病棟ごとの勤務人数の目安は以下です。

| 病棟 | 目標 |
|---|---|
| 1病棟 | 2〜3人 |
| 2病棟 | 4人 |
| 3病棟 | 3人以上 |

これらは固定勤務を変更してまで満たす条件ではなく、最適化時の目標として扱います。

### 単発勤務

```text
休 → 出 → 休
```

のような1日だけの勤務は禁止していません。

ただし、その他の条件が同程度の場合は、できるだけ避けるよう小さなペナルティを設定しています。

## 11. 最適化方法

OR-ToolsのCP-SAT Solverを使用し、優先順位ごとに段階的に最適化します。

### STEP 1：既存予定の変更を最小化

理由が付いていない既存の `出` や `休` についても、できるだけ変更しない勤務表を探します。

### STEP 2：休日数の最大偏差を最小化

一部の職員だけ休日数が大きく不足することを防ぎます。

例えば、

```text
A：0日不足
B：0日不足
C：3日不足
```

よりも、

```text
A：0.5日不足
B：1日不足
C：1日不足
```

のように、偏りの小さい状態を優先します。

### STEP 3：全員の休日数の差を最小化

最大偏差を抑えたうえで、全職員の必要休日日数との差をできるだけ0へ近づけます。

### STEP 4：その他の勤務条件を最適化

最後に、

- 病棟人数
- 専従・専任
- 作業療法士
- 4連続勤務
- 単発勤務

などを調整します。

この段階的な最適化によって、優先度の低い条件を満たすために重要な条件が犠牲になることを防いでいます。

## 13. 安全性への対応

Excel業務で利用することを想定し、元データを壊さないことを重視しています。

### 元ファイルを上書きしない

入力ファイル：

```text
input/kinmu_sample.xlsx
```

出力ファイル：

```text
output/kinmu_output.xlsx
```

として分離しています。

入力した勤務表そのものをPythonが上書きすることはありません。

### 一時ファイルを利用する

完成ファイルへ直接保存せず、一度、

```text
output/.kinmu_output.tmp.xlsx
```

へ保存します。

その後、

- Excel数式が変更されていないか
- 固定勤務が変更されていないか

を確認し、問題がなければ、

```text
output/kinmu_output.xlsx
```

へ置き換えます。

### Excel数式を保護する

処理開始時にExcel内の数式を記録します。

勤務表作成後に同じ数式が残っているかを確認し、変更があった場合はエラーとして処理します。

### 固定勤務を保存後にも検証する

OR-Tools上で固定するだけでなく、Excel保存後に再度読み込み、

```text
保存前の固定勤務
=
保存後の固定勤務
```

になっているか確認します。

### Excelの再計算

openpyxlはExcel数式そのものを計算しないため、出力ファイルをExcelで開いた際に数式が再計算されるよう設定しています。

## 14. 入力チェック

誤ったデータから勤務表を作成しないよう、最適化前に入力内容を検証します。

例えば、

```text
理由：希望
勤務：空白
```

のように理由だけが入力されている場合、自動的に意味を推測せずエラーとして停止します。

また、

```text
年休
↓
休
```

や、

```text
年/ または /年
↓
半/ または /半
```

などの組み合わせも確認します。

不正な入力がある場合は勤務表を生成せず、問題のセルをターミナルへ表示します。

## 19. 設計上のポイント

本プロジェクトでは、単に「休みを自動入力する」ことではなく、実際の業務で安全に利用できることを重視しました。

### 1. 既存業務を大きく変更しない

Excelを入力・出力として利用し、利用者が新しいシステムの操作方法を一から覚える必要を減らしています。

### 2. 人が入力した予定を最優先する

勤務と理由が入力された予定はハード制約として固定します。

### 3. 条件の優先順位を明確にする

```text
固定予定
↓
既存予定
↓
休日数
↓
人員配置
```

の順番で最適化します。

### 4. 元データを壊さない

入力ファイルと出力ファイルを分離しています。

### 5. 数式を保護する

保存前後でExcel数式を検証します。

### 6. Excelの行番号へ依存しすぎない

職員情報をA列から検索して取得します。

### 7. 半日を整数で扱う

0.5日を1単位として計算し、小数誤差を避けています。

### 8. 不可能な条件を無理に満たさない

すべてのソフト制約を満たせない場合でも、固定予定を壊してまで条件を成立させません。

### 9. エラー時に原因を確認できる

入力ミスや満たせなかった勤務条件をターミナルへ表示します。

## 20. 現在の仕様上の制限

現在は以下の制限があります。

### 職員・病棟構成がコード内に定義されている

現在、

```text
A〜P
```

の職員名と病棟構成をPythonコード側で定義しています。

そのため、職員追加・削除・名前変更・病棟異動にはコード修正が必要です。

### 半休の時間帯別人数を判定していない

現在は、

```text
半/
 /半
```

をその日に勤務者が存在するものとして扱います。

そのため、

```text
午前は人数を満たしている
午後は人数不足
```

といった時間帯別の人員配置までは判定していません。

### 委員会・研修・出張時の病棟在席を区別していない

現在は `出` として固定された勤務を勤務者として扱います。

そのため、

```text
委員会
研修
出張
```

などで実際には病棟を離れている時間がある場合でも、病棟勤務人数として計算される可能性があります。

### 前月末の勤務を考慮していない

連続勤務の判定は現在の月内のみです。

前月末から勤務が続いている場合の連続勤務は判定していません。

### Excelレイアウトに一定の形式が必要

日付・曜日・勤務欄・理由欄などの基本構造が大きく変更された場合は、コードの変更が必要になる可能性があります。

### 自動生成する半休には未対応

自動的に生成する勤務は、

```text
通常出勤
休
```

のみです。

新しい `半/`・`/半` は自動生成しません。

### GUIは未実装

現在はターミナルから実行します。

## 25. 技術的な見どころ

このプロジェクトで特に重視したのは、

> **現場で入力された勤務希望を壊さず、その条件内で可能な限り適切な勤務表を探索すること**

です。

単純なランダム配置や条件分岐だけではなく、OR-ToolsのCP-SAT Solverを利用して複数の条件を同時に評価しています。

また、

```text
固定予定
↓
既存予定
↓
休日数の公平性
↓
病棟・職種・連続勤務条件
```

という優先順位で段階的に最適化しています。

さらに、

- 入力ファイルを上書きしない
- 固定勤務を二重に保護する
- Excel数式を保存前後で検証する
- 一時ファイルを経由して保存する
- 入力異常を自動的に推測せずエラーとして扱う
- pytestで基礎ロジックを検証する

ことで、勤務表を「作れる」だけでなく、**業務で安全に扱うための設計**も意識しています。
