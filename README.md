# 勤務表作成支援ツール

[![Python Tests](https://github.com/thousand-boy/kinmu-automation/actions/workflows/pytest.yml/badge.svg)](https://github.com/thousand-boy/kinmu-automation/actions/workflows/pytest.yml)

Excelに入力した職員情報と勤務希望をもとに、勤務と休みの配置を調整するPythonのツールです。
普段使っているExcelを活かしながら、休日数・病棟の人数・職種・連続勤務などを確認できる勤務表の下書きを作ることを目指しています。

エンジニアへの転職を目指してPythonを学習する中で、身近な業務の課題を題材に開発しました。
現在は、条件と動作を検証するための試作品です。出力された勤務表をそのまま確定するのではなく、担当者が確認・調整してから使うことを想定しています。

> 初めて動かす方は、「環境の準備」から順に進めてください。最初は匿名化したサンプルで試せるので、実際の職員情報を入力する必要はありません。
> すでに準備が済んでいる方は、「日常の使い方」からお読みください。

## 1. できること・開発の背景

### 主な機能

- 勤務と理由を組み合わせて入力した予定を、変更せずに残す。
- 在籍職員に、公休数と入力済みの年休を合計した休日数を割り当てる。
- 日曜日の出勤人数を、各病棟ちょうど2名にする。
- 病棟の人数、専従・専任、作業療法士の配置を考慮する。
- 自動配置による4連勤や、細切れの勤務・休みをできるだけ減らす。
- 職員マスタを基準に、不足している職員の「勤務希望行＋理由欄行」を追加する。
- 在籍×の職員は行と入力を残したまま、最適化と休み集計の対象から外す。
- 出力前後の検証と、担当者が確認すべき条件の表示を行う。

### なぜ作ったのか

手作業で勤務表を作成する場合、ある職員の希望休を反映すると、別の日の人数や他の職員の連勤にも影響します。
休日数だけを合わせても職種や役割の配置が不足する場合があり、複数の条件を行き来しながら調整する必要があります。

そこで、業務の条件を「必ず守るもの」「できるだけ満たしたいもの」「人が判断するもの」に分け、配置の下書き作成と確認を支援する仕組みにしました。
特に重視したのは、理由を付けて固定した希望を勝手に変更しないことと、確認が必要な箇所を隠さずに示すことです。

作成後、リハビリテーションスタッフに目的・勤務条件・対応できる範囲を説明し、今後の進め方について了承を得ました。
実運用に向けては、整理した要件と試作品を院内のSESエンジニアに共有し、設計・開発・調整を引き継いでもらう方針です。
このREADMEでは、現在の実装と、ローカル環境で確認できた動作について説明します。

## 2. 使用するツールと基本用語

### このプロジェクトで使うもの

| ツール | 何をするものか | このプロジェクトでの用途 |
|---|---|---|
| Python | プログラムを実行する言語・実行環境 | Excelの読み込みから結果の保存までを実行する |
| Microsoft Excel | 表計算ソフト | 職員情報・希望を入力し、出力と数式の計算結果を確認する |
| openpyxl | PythonからExcelを読み書きするライブラリ | セル、数式、書式、職員行を扱う |
| Google OR-Tools | 条件を満たす組み合わせを探すライブラリ | CP-SATという計算機能で勤務を割り当てる |
| pytest | プログラムの動作を自動で確認するツール | 修正後も期待どおりの結果になるかを確認する |
| Git | ファイルの変更履歴を管理するツール | コードの変更を記録する。ZIPで試すだけなら不要 |
| GitHub | コードや説明を共有するサービス | リポジトリの公開とテスト結果の確認に使う |
| GitHub Actions | GitHub上で処理を自動実行する仕組み | コードの更新時にテストを実行する |

openpyxl・OR-Tools・pytestは、あとでまとめてインストールします。個別にダウンロードする必要はありません。
PythonからExcelアプリを自動操作するのではなく、保存済みの`.xlsx`ファイルを読み書きします。
GoogleのアカウントやAPIキーは不要です。勤務表の計算はローカル環境で行います。

### 手順に出てくる言葉

| 用語 | 意味 |
|---|---|
| ターミナル | 文字で命令を入力して操作する画面。ExcelやPythonの入力画面とは別のもの |
| コマンド | ターミナルに入力する命令。1行入力してEnterキーを押す |
| プロジェクト直下 | `README.md`・`requirements.txt`・`src`などが入っている最上位のフォルダ |
| パス | ファイルやフォルダの場所。`src/main.py`は「srcフォルダ内のmain.py」という意味 |
| ライブラリ | 他の開発者が提供している、再利用できる機能のまとまり |
| pip | Pythonのライブラリをインストールする仕組み |
| 仮想環境（venv） | このプロジェクト専用のPythonとライブラリの置き場所。今回は`.venv`を作る |
| マスタ | 判断の基準にする一覧。このツールでは「職員マスタ」が職員情報の正本 |
| 最適化 | 必須条件を守りながら、設定した評価ができるだけ良くなる組み合わせを探すこと |
| テスト | あらかじめ決めた入力と期待する結果を使って、プログラムの動作を確認すること |

仮想環境は、仮想マシンや別のパソコンのようなものではありません。フォルダ単位でライブラリを分けて管理するための仕組みです。
`python -m pip`は「今使っているPythonのpipを実行する」という指定です。別のPythonに誤ってインストールするのを防ぐために使っています。

<a id="setup"></a>
## 3. 環境の準備

### 3-1. 用意するもの

- Python 3.14系を利用できるMac。
- 入出力の`.xlsx`ファイルを編集・確認できるMicrosoft Excel。
- 初回のダウンロードとライブラリのインストールに使うインターネット接続。
- このリポジトリ一式。`main.py`だけでは動きません。

職員名や勤務情報を含む実データは使わず、最初は公開サンプルで確認してください。

### 3-2. Pythonを準備する

1. [Python公式のダウンロードページ](https://www.python.org/downloads/)から、Python 3.14系のmacOS用インストーラーを取得します。
2. `.pkg`ファイルを開き、案内に従ってインストールします。
3. 公式の手順に従い、`アプリケーション > Python 3.14`にある`Install Certificates.command`を実行します。
4. Spotlightなどから「ターミナル」を開き、次のコマンドを入力します。

```bash
python3.14 --version
```

`Python 3.14.x`と表示されれば準備完了です。末尾の数字は、インストールした更新版によって異なります。
macOSにもともと入っているPythonを置き換えたり、削除したりする必要はありません。
詳しくは[Python公式：macOSでPythonを使う](https://docs.python.org/ja/3.14/using/mac.html)を参照してください。

### 3-3. プロジェクトを取得する

Gitに慣れていない場合は、ZIPファイルで取得できます。

1. [このプロジェクトのGitHubページ](https://github.com/thousand-boy/kinmu-automation)を開きます。
2. `Code` → `Download ZIP`を選びます。
3. ダウンロードしたZIPを解凍します。ZIPの中身を表示するだけでなく、通常のフォルダとして展開してください。
4. 解凍したフォルダの中に`README.md`・`requirements.txt`・`src`・`sample`があることを確認します。

Gitを使う場合は、次の方法でも取得できます。

```bash
git clone https://github.com/thousand-boy/kinmu-automation.git
cd kinmu-automation
```

すでにプロジェクトが手元にある場合は、そのフォルダを使えます。
旧版から移行する場合は、`src/kinmu/`と新しいテスト・設定ファイルも必要です。`src/main.py`だけを差し替えても動きません。

### 3-4. 作業するフォルダへ移動する

以下は、ZIPを「ダウンロード」フォルダに解凍し、フォルダ名が`kinmu-automation-main`になった場合の例です。
保存場所やフォルダ名が異なる場合は、実際の場所に置き換えてください。パスに空白が含まれていても扱えるよう、引用符で囲んでいます。

```bash
cd "$HOME/Downloads/kinmu-automation-main"
pwd
ls
```

一覧に`README.md`・`requirements.txt`・`src`・`sample`が表示されれば、正しい場所にいます。
以降のコマンドは、すべてこの「プロジェクト直下」で実行します。

> コマンド欄の中身だけをコピーしてください。画面上の`$`・`>`や説明文は入力しません。
> 画面に`>>>`と表示されている場合は、Pythonの対話モードになっています。`exit()`を入力して対話モードを抜けてから、ターミナルで実行してください。

### 3-5. プロジェクト専用の仮想環境を作る

```bash
python3.14 -m venv .venv
source .venv/bin/activate
```

続けて、使用中のPythonを確認します。ここから先の`python`は、仮想環境内のPythonを指します。

```bash
python --version
python -c "import sys; print(sys.executable)"
```

Python 3.14系のバージョンと、プロジェクト内の`.venv`を含む実行ファイルの場所が表示されることを確認します。
行頭に`(.venv)`と表示される環境もありますが、実行ファイルの場所で確認するほうが確実です。

### 3-6. 必要なライブラリをインストールする

最初は、実行用とテスト用のライブラリをまとめてインストールします。

```bash
python -m pip install -r requirements-dev.txt
```

`-r`は「指定したファイルに書かれたライブラリを読み込む」という意味です。
`requirements-dev.txt`は実行用の`requirements.txt`も読み込むため、2つを別々に実行する必要はありません。
初回はダウンロードに時間がかかる場合があります。エラーが表示されずに終了したことを確認してください。

テストを行わず、実行だけできればよい場合は、代わりに`python -m pip install -r requirements.txt`を使っても構いません。

最後に、プログラムを起動できるかを確認します。

```bash
python src/main.py --help
```

`--input`と`--output`の説明が表示されれば、プログラムを起動する準備ができています。このコマンドでは勤務表は作成されません。

<a id="first-run"></a>
## 4. サンプルで初回実行する

### 4-1. 公開サンプルを使って実行する

仮想環境を有効にした状態で、プロジェクト直下から次を実行します。

```bash
python src/main.py --input sample/kinmu_sample.xlsx --output output/trial.xlsx
```

| 指定 | 意味 |
|---|---|
| `python src/main.py` | 勤務表の作成処理を起動する |
| `--input sample/kinmu_sample.xlsx` | 公開サンプルを読み込む |
| `--output output/trial.xlsx` | 試作結果を`trial.xlsx`という名前で保存する |

`output`フォルダがない場合は、自動で作成されます。入力したサンプルファイルは変更されません。
計算時間の上限は各モード60秒です。必要に応じて緩和モードも試すため、読み書きの時間を含めて数分程度かかると見込んでください。
計算中に画面が止まったように見えても、すぐに同じコマンドを重ねて実行しないでください。

### 4-2. 実行後の表示を確認する

成功すると、在籍人数、保存先、実行モード、個人別休日数などが表示されます。職員を追加した場合は、その職員名も表示されます。
まず、次の点を確認してください。

- `勤務表を作成しました`と保存先が表示されている。
- 在籍職員の個人別休日数が`残り0日`になっている。
- 通常モードと緩和モードのどちらで実行されたかを把握している。
- `⚠`が表示された場合は、その内容を読んでいる。

警告が出ても、処理が失敗したとは限りません。配置目標を満たせなかった箇所や、確認が必要な連勤を知らせる場合もあります。
一方、エラーで停止した場合は、出力ファイルがあっても今回の実行で作成されたものとは限りません。前回の出力が残っている可能性があるため、ファイルの更新日時も確認してください。

### 4-3. Excelを開いて確認する

プロジェクト内の`output/trial.xlsx`をMicrosoft Excelで開きます。
数式を再計算したうえで、希望・休日数・日曜人数・警告が出た条件を確認してください。
openpyxlは数式を計算しないため、Pythonで保存した直後のファイルと、Excelで再計算した後とで表示が異なる場合があります。

Excelの計算方法が「手動」になっている場合は、再計算してから保存してください。
自動計算の確認方法は、[Microsoft公式のExcel for Mac向け記事](https://support.microsoft.com/ja-JP/Excel/copy-a-formula-by-dragging-the-fill-handle-in-excel-for-mac)の末尾にある説明を参照してください。

<a id="daily-use"></a>
## 5. 日常の使い方

### 5-1. 入力用・出力用・公開用を分ける

| フォルダ | 用途 | 編集するときの注意 |
|---|---|---|
| `sample/` | GitHubでの公開と自動テストに使う匿名化サンプル | 実際の職員情報を書き込まない |
| `input/` | 日常の実行時に読み込むExcel | 勤務希望や職員マスタを編集する |
| `output/` | プログラムが生成した結果 | 確認・保管する。次回の実行で同名のファイルは置き換わる |

初回のみ、Finderで次の準備を行います。

1. プロジェクト直下に`input`フォルダを作ります。すでにある場合は、そのまま使います。
2. `sample/kinmu_sample.xlsx`をコピーし、`input`フォルダに貼り付けます。
3. ファイル名が`input/kinmu_sample.xlsx`になっていることを確認します。

すでに希望を入力したファイルがある場合は、サンプルで上書きしないよう注意してください。
拡張子を非表示にしている場合は、`kinmu_sample.xlsx.xlsx`のように拡張子が二重になっていないかも確認してください。

### 5-2. Excelを編集して実行する

1. `input/kinmu_sample.xlsx`のバックアップを取ります。
2. 入力Excelを開き、対象月の日付・曜日、職員マスタ、公休数、勤務希望と理由を確認・編集します。
3. Excelで再計算して保存します。入力ファイルや同名の出力ファイルをExcelで開いている場合は、閉じておきます。
4. ターミナルで、次を実行します。

```bash
python src/main.py
```

5. `output/kinmu_output.xlsx`とターミナルの表示を確認します。
6. 担当者が人数や現場の事情を確認し、勤務表を確定します。

引数を省略した場合は、`input/kinmu_sample.xlsx`を読み込み、`output/kinmu_output.xlsx`に出力します。
入力ファイルは変更されません。ただし、実行に成功すると、同名の既存の出力ファイルは新しい結果に置き換わります。
過去の結果を残したい場合は、実行前に別名で保管するか、出力ファイル名を指定してください。

### 5-3. 入出力名を指定する

例えば、別名で用意した入力ファイルを読み込み、結果も別名で保存する場合は次のとおりです。

```bash
python src/main.py --input input/kinmu_2026_10.xlsx --output output/kinmu_2026_10_v1.xlsx
```

この例の入力ファイルは、事前に自分で用意しておく必要があります。
パスに空白が含まれる場合は、`--input "input/勤務希望 10月.xlsx"`のように引用符で囲みます。
入力と出力に同じパスを指定することはできません。

既定の入出力先は、プログラムがあるプロジェクトの場所を基準に決まります。
`--input`・`--output`に相対パスを指定した場合は、コマンドを実行したフォルダが基準になります。
混乱を避けるため、このREADMEではプロジェクト直下から実行する前提で説明しています。

### 5-4. 次回起動するとき

仮想環境の作成とライブラリのインストールは、通常は初回のみです。新しいターミナルを開いたら、プロジェクト直下へ移動して仮想環境を有効化します。

```bash
source .venv/bin/activate
python src/main.py
```

作業を終えるときは、次のコマンドで仮想環境を解除できます。

```bash
deactivate
```

プロジェクトを別の場所へ移動した場合、仮想環境はそのままでは使えないことがあります。その場合は、新しい場所で作り直してください。
希望を編集しただけであれば、Pythonコードの変更やライブラリの再インストールは不要です。

<a id="excel-guide"></a>
## 6. 入力Excelの詳しい説明

### 6-1. 必要なシートとレイアウト

`Sheet1`と`職員マスタ`の2シートが必要です。新しいブックを一から作るのではなく、同梱サンプルのコピーを編集して使ってください。

| Sheet1の場所・項目 | 内容 |
|---|---|
| 2行目 | 日付 |
| 3行目 | `月`・`火`・`水`・`木`・`金`・`土`・`日`の1文字で表した曜日 |
| C〜AG列 | 最大31日分の勤務・理由を入力する範囲 |
| A列 | 職員IDまたは表示名。役割を付記して表示する場合もある |
| B列 | 各職員の`勤務希望`と、その直下の`理由欄` |
| `公休数`列 | 各職員の公休数。見出しは上部3行以内に必要 |
| `階休み`行 | 上から1・2・3病棟の順で3行必要 |
| `全体休み`行 | 全病棟の休みを集計する1行が必要 |

対象月の日付と曜日は、利用者が確認・更新します。日付から曜日を自動で判定する機能はありません。
31日未満の月は、使わない末尾の列の「日付と曜日」を両方とも空欄にしてください。
途中の日付列を飛ばしたり、曜日を`月曜`など別の表記にしたりしないでください。

職員1人につき、次の2行を使います。この構成と病棟ごとの並び、集計行は崩さないでください。

| A列 | B列 | 1日 | 2日 | 3日 |
|---|---|---|---|---|
| A | 勤務希望 | 休 | 出 | （空欄） |
| （氏名欄は結合） | 理由欄 | 希望 | 委員会 | （空欄） |

### 6-2. 職員マスタの入力

1行目に次の7つの見出しが必要です。見出しの文字は変更しないでください。

| 職員ID | 表示名 | 病棟 | 専従 | 専任 | 作業療法士 | 在籍 |
|---|---|---|---|---|---|---|
| Q | Q | 3 | × | × | × | ○ |

上の行は、3病棟の一般職員Qを追加する例です。

- 職員ID・表示名・病棟は必須です。職員IDは、退職者も含めて重複しないようにします。
- 在籍職員の表示名も重複しないようにします。他の職員のIDと紛らわしい名前も避けてください。
- 病棟は整数の`1`・`2`・`3`で入力します。`3病棟`のような文字列は入力しないでください。
- 専従・専任・作業療法士・在籍の欄は、上の表の`○`・`×`をコピーして使えます。
- 同じ職員の専従と専任を、両方とも○にすることはできません。
- 在籍欄が空欄の場合は×として扱います。対象者の漏れを防ぐため、○か×を明示してください。
- 各病棟に在籍職員が2名以上、全体で在籍中の作業療法士が1名以上必要です。ただし、これを満たしていても、すべての条件を満たせるとは限りません。

> `○`と`◯`は見た目が似ていますが、別の文字です。現在のコードでは`◯`はエラーになります。迷った場合は、このREADMEの`○`をコピーしてください。

### 6-3. 勤務と理由の入力

| 勤務欄 | 入力時の意味 | 自動調整との関係 |
|---|---|---|
| 空欄 | まだ割り当てを決めていない | 自動調整の対象 |
| `出` | 出勤予定 | 理由がなければ、調整で変わる場合がある |
| `休` | 1日休み | 理由がなければ、調整で変わる場合がある |
| `半/`・`/半` | 半日休み | 確定した予定は理由を付けて入力する |

理由欄に入力できる文字は、`希望`・`委員会`・`年休`・`年/`・`/年`・`研修`・`特休`・`出張`です。
勤務と有効な理由の両方を入力した予定は「固定勤務」として扱い、変更しません。

| 勤務欄 | 理由欄 | 扱い |
|---|---|---|
| `休` | `希望` | 希望休として固定する |
| `出` | `委員会` | 出勤予定として固定する |
| `休` | `年休` | 1日の年休として固定する |
| `半/` | `年/` | 半日の年休として固定する |
| `/半` | `/年` | 半日の年休として固定する |
| `休` | 空欄 | なるべく維持するが、変更する場合がある |
| 空欄 | `希望` | 勤務が未入力のため入力エラー |
| `出` | `年休` | 年休との組み合わせが不正なため入力エラー |

「休」と書くだけでは、必ず残るとは限りません。変更されては困る希望には、理由も入力してください。
半休も理由がないと固定予定にはならず、通常出勤や終日休みに置き換わる場合があります。
このプログラムは、新しい半休を自動生成しません。

出力では、通常出勤を空欄で表します。入力済みの`出`を維持したセルは`出`のまま残り、自動で割り当てた終日休みには`休`が入ります。
そのため、空欄の意味は入力では「未確定」、出力では「通常出勤」と、場面によって異なります。
理由欄は書き換えません。

### 6-4. 公休数・年休・半休の計算

必要休日数は、職員ごとの公休数と、理由欄に入力済みの年休を合計した日数です。

```text
必要休日数 = 公休数 + 入力済みの年休の日数

年休の加算：年休 = 1日、年/・/年 = 0.5日
休みの割当：休   = 1日、半/・/半 = 0.5日
```

例えば、公休8日・年休1日なら、必要休日数は9日です。固定した年休1日も、割り当て済みの休みとして数えます。
年休を公休数の欄にも含めてしまうと、二重に計上されます。
`特休`など年休以外の理由による休みも、割当休日数には含まれます。ただし、必要休日数に別途加算する処理はありません。現場での扱いと合っているか確認してください。

公休数は0以上の数値で、`8`・`8.5`のように0.5日単位で入力します。`8日`のような文字列は使いません。
数式の場合は、単純なセル参照か、Excelが保存した計算済みの数値を読み取ります。
読み取れない場合は、Excelで再計算して保存してください。PythonがExcelの数式全般を計算するわけではありません。

固定休が必要休日数を超える場合、調整できる日が足りない場合、半日単位が合わない場合は、処理を停止します。
特に、自動生成する休みは1日単位のため、0.5日を含む休日数にするには、固定した半休と組み合わせる必要があります。

`階休み`と`全体休み`の数式は、在籍者だけを集計する形に更新します。半休は、この休み集計では0.5として数えます。

<a id="staff-management"></a>
## 7. 職員の追加・退職・変更

### 7-1. 増員を試す

普段の入力ファイルとは別のコピーを使い、架空の職員Qで確認します。

1. 入力Excelのコピーを`input/staff_trial.xlsx`として保存します。
2. コピーした職員マスタに前章の例のQを追加し、在籍を○にします。Qがすでにいる場合は、重複しない別のID・表示名を使います。
3. Excelで保存して閉じます。
4. 次を実行します。

```bash
python src/main.py --input input/staff_trial.xlsx --output output/staff_trial.xlsx
```

5. 出力のSheet1で、3病棟の集計行の前にQの2行が追加されていることを確認します。
6. 氏名・役割、罫線、行高、公休数の数式、休日数、日曜人数を確認します。

不足している在籍職員の行は、同じ病棟にある既存の2行を雛形にして追加します。
書式・行高・氏名欄の結合・入力規則・条件付き書式・個人の数式は引き継ぎます。勤務と理由は空欄の状態から配置します。
対応しているExcel機能の範囲については、[現在の制限](#limitations)も参照してください。

**職員マスタを編集した時点で、Sheet1に行が追加されるわけではありません。Pythonを実行した後の「出力Excel」に反映されます。**
入力Excel自体に新しい行が保存されることはありません。

### 7-2. 新しい職員の希望を入力する

職員マスタに追加しただけの状態では、初回の実行時にその職員の希望はまだ入力されていません。
希望を入力するには、行が追加された出力Excelを別名でコピーし、次回の入力ファイルにします。そのうえで、その職員の勤務・理由を入力して再実行します。

例えば、前の手順で作成された`output/staff_trial.xlsx`を、`input/staff_trial_with_requests.xlsx`へコピーします。
ExcelでQの希望を入力して保存し、次を実行します。

```bash
python src/main.py --input input/staff_trial_with_requests.xlsx --output output/staff_trial_v2.xlsx
```

コピー先に既存の入力ファイルがある場合は、上書きせずに別名にしてください。
出力ファイルを入力として使う場合、他の職員に自動配置された`休`もそのまま残ります。理由のない勤務は再調整の対象ですが、なるべく維持するように評価される点にも注意してください。
翌月へ流用するときは、日付・曜日・前月の勤務と理由を見直し、古い固定予定を残さないでください。

### 7-3. 退職・休職を試す

1. テスト用のコピーで、対象職員の在籍を×にします。
2. 職員マスタの行自体は削除せず、保存して再実行します。
3. 元の勤務希望行・理由欄行と、その入力内容が残っていることを確認します。
4. 個人別休日数の表示と、病棟・全体の休み集計から外れていることを確認します。

現在は、行を削除するのではなく「対象から外して保存する」方法で整理します。行を自動で削除する機能はありません。
既存の行と職員マスタの対応を保つため、退職者のマスタ情報も残します。
在籍を○に戻すと、再び最適化と集計の対象になります。

退職者の個人欄の数式は残るため、Excel上にその職員の休日残りが表示される場合があります。これは在籍者の休日不足としては数えません。
在籍する最後の作業療法士を×にした場合や、病棟の在籍人数が2名未満になる場合など、必須条件が成立しなくなるときは処理を停止します。

### 7-4. 病棟・役割・表示名を変えるとき

病棟と役割は、職員マスタを基準に判定します。役割は出力の表示にも反映されます。
ただし、既存職員の病棟を変更しても、その職員の2行を別の病棟の位置へ自動で移動する機能はありません。計算上の所属と、表上の位置がずれる場合があります。

Sheet1の氏名は、職員IDまたは表示名で照合します。
Sheet1に旧表示名しかない状態でマスタの表示名を変更すると、照合できなくなる場合があります。
必要に応じてSheet1の氏名欄も合わせて修正し、必ずコピーしたファイルで動作を確認してください。

<a id="scheduling"></a>
## 8. 勤務配置の条件と結果の読み方

### 8-1. 必ず守る条件（ハード制約）

通常・緩和のどちらのモードでも、次の条件を同時に満たします。

- 勤務と理由を入力した固定予定を変更しない。
- 在籍職員全員に、必要休日数をちょうど割り当てる。
- 日曜日は、各病棟ちょうど2名が出勤する。

条件が矛盾する場合でも、希望を勝手に変更したり、休日数を減らしたりして出力することはありません。
半休は、日曜などの出勤人数では1名として数えます。一方、終日勤務の連続を数える際は、連勤の区切りとして扱います。
午前・午後別の人数は、この数え方だけでは確認できません。

### 8-2. できるだけ満たしたい条件（ソフト制約）

| 対象 | 目標 |
|---|---|
| 月〜土・各病棟 | 専従または専任を1名以上配置する |
| 月〜土・全病棟合計 | 作業療法士を1名以上、可能なら2名配置する |
| 月・火・土・1病棟 | 出勤人数を2〜3名にする |
| 月・火・土・2病棟 | 出勤人数を4名にする |
| 月・火・土・3病棟 | 出勤人数を3名以上にする |
| 水・木・金・各病棟 | 休みを2名以内に近づけ、4名以上の休みをより強く避ける |
| 理由のない既存の`出`・`休` | なるべく維持する |
| 勤務の並び | `休→出→休`や`出→休→出`などの細切れを減らす |

満たせない目標には、重要度に応じた点数（ペナルティ）を付けて計算します。
これらの目標は、すべてを必ず達成するものではありません。必要休日数・固定予定・日曜人数を守っていても、人数目安などの警告が出る場合があります。

### 8-3. 通常モードと緩和モード

| モード | 4連続の終日勤務の扱い |
|---|---|
| 通常（strict） | 自動配置による4連勤を禁止する。固定予定だけで成立する4連勤は保持して警告する |
| 緩和（relaxed） | 通常モードで解が見つからない場合に試す。4連勤を許容するが、削減を最優先で評価する |

緩和するのは4連勤の条件だけです。固定予定・休日数・日曜人数は緩和しません。
計算時間の上限は各モード60秒です。「条件が両立しないと確認された場合」と「制限時間内に解が見つからなかった場合」は区別して扱います。
時間切れになったというだけで、勤務表が存在しないと断定することはできません。

評価の優先順位は、緩和時の4連勤削減 → 人数・役割などの原則条件 → 既存勤務の維持などの希望条件です。
必須条件は、この優先順位に沿って妥協するものではなく、常に同時に守ります。

### 8-4. 表示の意味

| 表示・状態 | 意味・対応 |
|---|---|
| `OPTIMAL`／最適性まで証明 | 設定した評価方法のもとで最適と確認できた。現場にとっての最良を保証するものではない |
| `FEASIBLE`／実行可能解 | 必須条件を満たす解はあるが、最適性までは証明していない |
| 休日数の`残り0日` | その在籍職員の必要休日数と割当数が一致している |
| 固定勤務だけの4連勤 | 入力済みの予定を残した結果。予定自体を担当者が確認する |
| 緩和で発生した4連勤 | 自動配置で残った連勤。調整が必要かどうかを担当者が確認する |
| 満たせなかった原則・希望条件 | 設定した目標との差。出力に成功していても内容の確認が必要 |
| 入力エラー／作成できない | 今回の出力は完了していない。入力・条件またはエラー内容を確認する |

5日以上の連勤は、重なり合う複数の4日区間として表示される場合があります。
出力を手作業で修正すると、別の職員の休日数や日曜人数が変わることもあります。
重要な予定を変更した場合は、入力側にも反映して再実行し、最終的な勤務表をもう一度確認してください。

## 10. 処理の流れとコードを整理した理由

### 10-1. 実行中に行っていること

```text
入力Excelを読み込む（数式と計算済み値をそれぞれ取得）
  ↓
職員マスタを検証し、不足する職員の2行を追加する
  ↓
在籍職員・日付列・勤務と理由・必要休日数を確認する
  ↓
日曜の固定人数を確認し、在籍者だけの休み集計式へ更新する
  ↓
通常モードで配置を計算し、必要なら4連勤だけを緩和する
  ↓
勤務をExcelへ書き込み、固定勤務・数式・休日数を検証する
  ↓
一時ファイルへ保存し、再読み込みして検証する
  ↓
検証が通ったファイルで、正式な出力を置き換える
  ↓
結果と、担当者が確認すべき条件を表示する
```

一時ファイルは、出力先と同じフォルダに作成します。保存・再読み込み・検証・置換のいずれかに失敗した場合は、前回の出力を残したまま一時ファイルを片付けます。
入力と出力を分けることに加えて、不完全な結果で前回の出力を置き換えないようにするための設計です。ただし、利用者自身によるバックアップも別途必要です。

数式は、行追加に伴う補正と集計式の更新を行った後に記録し、その後の書き込み・保存で変わっていないかを確認します。
入力時点の数式を一切変更しない、という意味ではありません。

### 10-2. リファクタリングで整理したこと

初期の実装では、Excel操作から計算・表示までを1つの大きな`main.py`にまとめていました。
機能が増えるにつれて修正箇所を探しにくくなったため、勤務条件を変えずに、役割ごとのモジュールへ分割しました。
あわせて、入力や保存で失敗した場合に備える確認も追加しました。

| 整理した点 | そうした理由 |
|---|---|
| Excel操作・検証・最適化・表示を分離 | 変更の目的に応じて確認する場所を絞り、1つのファイルに異なる責任を集めないため |
| `run(input_file, output_file)`へパスを渡す | テストでは一時フォルダを指定し、実データと分けて確認できるようにするため |
| `dataclass`で職員などの項目を定義 | 関数間で渡すデータの意味を明確にするため |
| `Counter`など標準ライブラリを利用 | 集計の意図をそのまま表し、自前で書くループや重複した処理を減らすため |
| 0.5日を1単位として整数化 | CP-SATの整数制約で、半日を含む休日数を扱うため |
| 人数目安・記号・重みを定数に集約 | 同じ設定を複数箇所に書かず、変更箇所を分かりやすくするため |
| 一時保存→再検証→置換 | 検証が終わるまで前回の出力を残すため |
| コメントを判断の理由に絞る | コードをなぞるだけのコメントを減らし、勤務条件やExcel操作の注意点が伝わるようにするため |

職員行を追加する際、`insert_rows()`を呼ぶだけでは数式の依存関係までは補正されません。
このツールでは、対応する参照、結合セル、行高、入力規則、条件付き書式などを独自の処理で補正・複製しています。
これは、[openpyxl公式の行挿入に関する注意](https://openpyxl.readthedocs.io/en/stable/editing_worksheets.html)を踏まえた対応です。

<details>
<summary>コードを読む方へ：条件の優先順位の付け方</summary>

必須条件は、計算モデルに直接設定します。それ以外の条件は、違反量と重みから点数を算出し、その合計が小さくなる配置を探します。
ただし、単にすべての点数を足し合わせるだけでは、多数の小さな改善と引き換えに、重要な条件が悪化する可能性があります。

そこで、下位条件の点数の上限を計算し、上位条件での1ポイントの改善が、下位条件すべての悪化を上回るように係数を設定しています。
この仕組みにより「4連勤削減 > 原則条件 > 希望条件」の段階を保っており、`tests/test_optimizer.py`でも確認しています。
各段階の中では設定した重みで調整するため、同じ段階にあるすべての目標を個別に保証するものではありません。

計算は、検索ワーカー1つ・乱数シード42に固定しています。ただし、時間制限があるため、環境やバージョンの違いも含めて、毎回まったく同じ勤務表になることは保証していません。

</details>

## 12. うまく動かないとき

### 12-1. 最初に確認すること

1. プロジェクト直下にいるか。
2. `.venv`のPythonを使っているか。
3. 実行対象は`sample`・`input`のどちらか、保存先はどこか。
4. Excelで編集した内容を保存したか。
5. 同名の出力Excelを開いたままにしていないか。

Pythonのエラーは、長い`Traceback`の最後に原因が書かれていることがよくあります。
現時点では、すべてのエラーを短い日本語のメッセージにまとめて表示する画面までは用意していません。
最後に表示されるエラー名・メッセージと、指摘されたシート・セルを確認してください。

### 12-2. よくある症状と対処

| 症状・メッセージ | 確認・対処 |
|---|---|
| `python`や`python3.14`が見つからない | Pythonのインストールを確認し、ターミナルを開き直す。「Pythonを準備する」の手順に戻る |
| `>>>`が表示され、コマンドを入力すると構文エラーになる | Pythonの対話モードになっている。`exit()`で抜けてから実行する |
| `can't open file ... src/main.py` | 作業フォルダが違う、ZIPが解凍されていない、またはファイルが不足している。プロジェクト直下の一覧を確認する |
| `No module named openpyxl`・`ortools`・`pytest` | 仮想環境と`sys.executable`を確認し、そのPythonでrequirementsをインストールする |
| `No module named kinmu` | `src/kinmu/`を含む一式がそろっているか確認する。入口は`python src/main.py`、テストは`python -m pytest`で実行する |
| `勤務表が見つかりません` | 入力ファイルの場所・ファイル名・拡張子を確認する。初回は`--input sample/kinmu_sample.xlsx`で試す |
| 必要なシート・見出しがない | `Sheet1`・`職員マスタ`と、マスタの7つの見出しを確認する。別の書式のExcelではなく、サンプルのコピーを使う |
| `「◯」を○/×として認識できません` | 指摘されたセルの文字を、このREADMEの`○`に置き換える |
| 職員がマスタに見つからない・重複する | Sheet1の氏名とマスタのID・表示名を照合する。退職者のマスタ行も削除せずに残す |
| 病棟や職員の範囲を判定できない | 病棟が1〜3になっているか、2行構成と病棟ごとの並び、集計行が保たれているかを確認する |
| 曜日を認識できない | 3行目の曜日を1文字にする。使わない末尾の列は、日付・曜日を両方とも空欄にする |

| 公休数の数値を取得できない | 数値・参照先を確認し、Excelで再計算して保存する。循環参照がある場合は数式を修正する |
| 固定休日が多すぎる・休日を割り当てられない | 公休数と年休の二重計上、固定休の数、固定出勤の多さ、半日単位の整合性を確認する |
| 日曜日の人数条件を満たせない | 同じ病棟の日曜に固定出勤が3名以上いないか、出勤可能者が2名未満になっていないかを確認する |
| 緩和しても勤務表を作成できない | 固定勤務・必要休日数・日曜2名が両立するかを確認する。時間切れと両立不能を区別して読む |
| `PermissionError`・出力を置き換えられない | 出力ファイルをExcelで開いている場合は閉じる。保存先の権限も確認する |
| 数式の結果が空欄・古いまま | Excelで開き、計算方法と再計算を確認して保存する。openpyxlは数式を計算しない |
| エラー後も出力ファイルがある | 前回のファイルの可能性がある。今回の成功表示と更新日時を確認する |

`MODEL_INVALID`や「数式が変更されました」など、内部処理の不整合を示す表示が出た場合は、結果を採用せずに原因を調べてください。
入力を直せば済む問題とは考えず、サンプルでも再現するかどうかと、自動テストの結果を確認します。

## 13. 対応範囲と今後の課題

| 現在の対応・制限 | 今後検討したいこと |
|---|---|
| 病棟は1・2・3。人数や役割の目標はコードに定義 | 条件を設定ファイルで変更できるようにする |

| 自動生成するのは通常出勤と終日休みだけ | 半休の自動配置を検討する |
| ターミナルから操作する。エラー時はTracebackも表示される | 操作画面と分かりやすいエラー表示を用意する |

### Excelについての制限

行追加・参照補正は、同梱テンプレートとA1形式の直接参照を前提にしています。
名前定義、テーブル、グラフ、印刷範囲などの依存関係や、他シートの入力規則・条件付き書式までは自動で補正しません。
openpyxl自体も、Excelのすべての機能を保持できるわけではありません。
マクロ付きのファイルや、レイアウトを大きく変更したブックは対象外で、別途対応が必要です。

### 人が最終確認すること

- 希望休・予定が意図どおりに固定されているか。
- 在籍者の休日残りが0で、日曜人数が合っているか。
- 警告が出た人数・役割・連勤を許容できるか。
- 午前・午後の人数、前月からの連勤、負担の偏りが適切か。
- 委員会・研修・出張などで病棟を離れる人を考慮できているか。
- 現場の就業ルールや個別の事情に合っているか。

このツールは勤務表の作成を支援するものであり、労務上の適合性や医療現場の安全性を自動で保証するものではありません。
